# mTLS Certificate Binding: Worker → AWS

This document explains the end-to-end setup for the `aspire-math` Worker to call an external AWS server with mutual TLS (mTLS) verification.

## Architecture

```
Browser
  ↓
Worker (aspire-math)
  ↓ (with mTLS Binding)
AWS Server:9000 (FastAPI with client cert verification)
```

## Prerequisites

- Self-signed certificates: CA, server, client (generated by `knuth/certs/generate-certs.sh`)
- AWS server running FastAPI with mTLS requirement on port 9000
- Cloudflare Worker project with Wrangler CLI access

## Steps

### 1. Generate Certificates (One-time)

```bash
cd worker_pages/knuth/certs
./generate-certs.sh
# Outputs: ca-cert.pem, server-cert.pem, server-key.pem, client-cert.pem, client-key.pem
```

### 2. Upload mTLS Certificate to Cloudflare

The **mTLS Certificate Binding** is NOT the same as environment secrets. It's a special Cloudflare resource that allows Pages Functions to present client certificates on outbound fetch() calls.

```bash
cd worker_pages/workers/aspire-math

wrangler mtls-certificate upload \
  --cert ../knuth/certs/out/client-cert.pem \
  --key ../knuth/certs/out/client-key.pem \
  --name knuth-cert
```

Returns a certificate ID (e.g., `27c02a84-6d1b-4cb7-8d24-d79250cd324e`).

### 3. Configure wrangler.toml

Add the mTLS binding to `worker_pages/workers/aspire-math/wrangler.toml`:

```toml
[[mtls_certificates]]
binding = "LAPTOP_BACKEND_MTLS"
certificate_id = "27c02a84-6d1b-4cb7-8d24-d79250cd324e"
```

This creates a `Fetcher` interface available in the Worker as `env.LAPTOP_BACKEND_MTLS`.

### 4. Use in the Worker

In `workers/aspire-math/src/index.ts`:

```typescript
import type { Fetcher, PagesFunction } from '@cloudflare/workers-types';

interface Env {
  LAPTOP_BACKEND_MTLS: Fetcher;
}

export const onRequestGet: PagesFunction<Env> = async ({ request, env }) => {
  const url = new URL(request.url);
  
  // Fetcher automatically presents the client cert on the fetch() call
  const response = await env.LAPTOP_BACKEND_MTLS.fetch(
    `https://15.206.133.75:9000/multiply?${url.searchParams.toString()}`
  );

  return new Response(await response.text(), {
    status: response.status,
    headers: { 'Content-Type': 'application/json' }
  });
};
```

**Key point**: The `Fetcher` automatically handles mTLS — no manual cert presentation needed. Cloudflare manages the TLS handshake.

### 5. Test Locally

```bash
cd worker_pages/workers/aspire-math
wrangler dev
```

The Pages frontend calls `/api/add`; `/multiply` is handled by the Worker.


## Key Differences: Secrets vs mTLS Binding

| | Secrets | mTLS Binding |
|---|---------|-------------|
| **Used for** | Environment variables | Client cert on outbound HTTPS |
| **Set via** | `wrangler pages secret put` | `wrangler mtls-certificate upload` |
| **Available in env** | `env.SECRET_NAME` (string) | `env.BINDING_NAME` (Fetcher interface) |
| **Presents client cert?** | ❌ No — fetch() API can't use it | ✅ Yes — Fetcher auto-presents |
| **Use case** | API keys, database URLs | mTLS to external services |

## End-to-End Flow

1. **Client** → `GET /multiply?a=5&b=6` on `aspire-math`
2. **Worker** receives request
3. **Worker** uses `env.LAPTOP_BACKEND_MTLS.fetch()` with the AWS endpoint
4. **Cloudflare Edge** initiates TLS connection to AWS, presents client cert
5. **AWS FastAPI** verifies client cert against CA
6. **AWS FastAPI** returns `{"a": 5, "b": 6, "result": 30}`
7. **Worker** returns response to browser
8. **Browser** displays result

## Troubleshooting

**Issue**: `Error: certificate_id not found`
- Ensure you ran `wrangler mtls-certificate upload` and got a valid ID
- Double-check the ID in wrangler.toml matches the output

**Issue**: `Error: mTLS handshake failed`
- Ensure AWS server is running and port 9000 is open
- Verify the server cert is signed by the CA (client will verify it)
- Check AWS security group allows inbound on 9000

**Issue**: Hostname mismatch warning
- Server cert is for `port9000.awanipro.com`, but we call IP `15.206.133.75`
- This is expected for testing; in production, use a DNS name matching the cert
